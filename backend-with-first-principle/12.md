# 1. What is a Database?

A **database** is an organized collection of data that allows storing, retrieving, updating, and deleting information efficiently.

Without databases:

- Data disappears when programs stop.
- No long-term storage.
- Difficult to manage large datasets.

Example:

Instead of

```
Todo List
---------
Buy Milk
Study Java
Sleep
```

stored only in program memory,

we store it permanently inside a database.

---

# 2. Persistence

## Definition

Persistence means:

> Data continues to exist even after the application is closed or the computer restarts.

Example:

Without persistence:

```
Open App
↓
Create Account
↓
Close App
↓
Everything Gone
```

With persistence:

```
Open App
↓
Create Account
↓
Database Stores Data
↓
Close App
↓
Open Again
↓
Account Still Exists
```

This is the primary purpose of databases.

# 3. Storage (Disk vs RAM)

## RAM

- Very fast
- Expensive
- Temporary
- Data lost after shutdown

Examples:

- Cache
- Redis
- Variables in programs

---

## Disk

- Permanent
- Cheap
- Large storage
- Slower than RAM

Examples:

- PostgreSQL
- MySQL
- MongoDB

---

### Why Databases Use Disk

Suppose you have

```
100 Million Users
```

Keeping all users in RAM would cost enormous money.

Instead,

Database stores everything on disk and loads required pages into memory.

# 6. Relational vs Non-Relational Databases

## Relational Database

Stores data in tables.

Example

Users

| id | name |
|----|------|
|1|John|

Orders

| id | user_id |
|----|----------|
|5|1|

Relationship via Foreign Key.

Uses SQL.

Examples

- PostgreSQL
- MySQL
- SQL Server

---

### Advantages

✔ Strong consistency

✔ ACID transactions

✔ Structured

✔ Relationships

✔ Mature ecosystem

---

## Non-Relational Database

Stores documents.

Example MongoDB

```json
{
  "name":"John",
  "skills":[
      "Java",
      "Spring"
  ]
}
```

Schema can vary.

---

### Advantages

- Flexible
- Easy scaling
- Good for unstructured data

---

### Drawbacks

- Relationships harder
- Less strict

---

```

Stores whole numbers.

Example

```

---

## Decimal

```

```

Stores exact numbers.

Good for

Example

```

```

---

Approximate values.

Not recommended for money.

---

## Text

Preferred over

```

```

Reason:

No unnecessary length restrictions.

Less migrations.

Simpler.

---

## Boolean

```

FALSE
```

---

## Date

Stores only date.

Example

```

```

---

## Timestamp

Date + Time

Example

```

```

---

## UUID

Universally Unique Identifier.

Example

```

---

```

Docker

---

Advantages

# 9. Database Migrations

A migration tracks database changes over time.

Instead of editing schema manually,

we create version-controlled files.

Example

```
001_create_users.sql
```

Later

```
002_add_email.sql
```

---

## Up Migration

Applies changes.

Example

```
CREATE TABLE users(...)
```

---

## Down Migration

Undo changes.

Example

```
DROP TABLE users
```

---

Benefits

✔ Version control

✔ Easy rollback

✔ Team collaboration

# 13. Constraints

Constraints protect data quality.

---

## Primary Key

Unique identifier.

```
PRIMARY KEY(id)
```

---

## Foreign Key

Maintains relationship.

Example

```
Orders.user_id

↓

Users.id
```

---

### ON DELETE CASCADE

Delete parent

↓

Delete child automatically.

---

### ON DELETE RESTRICT

Cannot delete parent

until child removed.

---

## CHECK Constraint

Example

```sql
CHECK(age>18)
```

Rejects invalid data.

# 19. Indexes

Without Index

Database scans every row.

Complexity

O(n)

---

With Index

Uses B-Tree.

Much faster.

Similar to book index.

Instead of reading entire book,

go directly to page.

---

Example

```sql
CREATE INDEX idx_email
ON users(email);
```

Search by email becomes much faster.

To speed up searching.

Prevent SQL Injection.
