# 1. Introduction to HTTP

HTTP stands for:

**HyperText Transfer Protocol**

It is the foundational communication protocol of the web.

Every time you:

- Open a website
- Submit a login form
- Upload an image
- Call an API
- Use a mobile app

HTTP is usually involved behind the scenes.

Backend engineers spend most of their careers handling HTTP requests and responses.

Understanding HTTP is essential before learning:

- REST APIs
- Express.js
- NestJS
- Authentication
- Microservices
- GraphQL
- Web Security

---

# 2. Core Principles of HTTP

HTTP is built around two major principles:

## Statelessness

HTTP does not remember previous requests.

Every request is independent.

Example:

### Request 1

```http
GET /profile
```

### Request 2

```http
GET /orders
```

The server treats these as completely separate requests.

---

### What does this mean?

The server does NOT automatically know:

- Who you are
- Whether you logged in earlier
- What you did previously

Every request must carry its own information.

Examples:

```http
Authorization: Bearer token
```

or

```http
Cookie: session_id=abc123
```

---

### Benefits of Statelessness

#### Simpler Servers

No need to remember every user's state.

#### Better Scalability

Requests can be handled by any server.

#### Better Reliability

Server crashes do not destroy client state.

#### Easier Load Balancing

Any request can go to any server.

---

## Client-Server Model

Communication always begins from the client.

### Client Examples

- Browser
- Mobile App
- Postman
- Curl
- Frontend Application

### Server Examples

- Express Server
- NestJS Server
- Django Server
- Spring Boot Server

Flow:

```text
Client
   |
Request
   |
   V
Server
   |
Response
   |
   V
Client
```

The server waits for requests.

The client initiates communication.

---

# 3. HTTP in the OSI Model

HTTP operates at:

```text
Layer 7 (Application Layer)
```

OSI Model:

```text
7 Application  ← HTTP
6 Presentation
5 Session
4 Transport    ← TCP / UDP
3 Network      ← IP
2 Data Link
1 Physical
```

HTTP focuses on:

- Request format
- Response format
- Headers
- Methods
- Status codes

It relies on lower layers for actual delivery.

# 5. Transport Protocols and HTTP Versions

HTTP itself does not transport data.

It uses transport protocols underneath.

---

## HTTP 1.0

Behavior:

```text
1 Request
=
1 TCP Connection
```

Example:

```text
GET /users
```

Connection opens.

Response returns.

Connection closes.

Problems:

- Slow
- Expensive
- High latency

---

## HTTP 1.1

Introduced:

```text
Keep-Alive
```

Multiple requests use the same TCP connection.

Example:

```text
GET /users
GET /products
GET /orders
```

All can reuse one connection.

Benefits:

- Faster
- Less overhead
- Better performance

---

## HTTP 2

Major improvements:

### Multiplexing

Multiple requests simultaneously.

```text
Request A
Request B
Request C
```

Same connection.

No waiting.

---

### Binary Framing

More efficient than plain text.

---

### Header Compression

Reduces network usage.

---

### Server Push

Server can proactively send resources.

---

## HTTP 3

Uses:

```text
QUIC
```

instead of TCP.

QUIC is built on UDP.

Benefits:

- Faster connection setup
- Better mobile performance
- Reduced latency
- No head-of-line blocking

# 6. Anatomy of HTTP Messages

Communication happens using messages.

Two types:

1. Request Message
2. Response Message

---

# Request Message Structure

Example:

```http
POST /users HTTP/1.1
Host: api.example.com
Content-Type: application/json

{
  "name": "John"
}
```

Components:

### Request Line

```http
POST /users HTTP/1.1
```

Contains:

- Method
- URL
- HTTP Version

---

### Headers

Metadata.

Example:

```http
Content-Type: application/json
Authorization: Bearer token
```

---

### Blank Line

Separates headers and body.

---

### Request Body

Contains data.

Example:

```json
{
  "name": "John"
}
```

---

# Response Message Structure

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 1,
  "name": "John"
}
```

Contains:

- HTTP Version
- Status Code
- Status Text
- Headers
- Body

---

# 7. HTTP Headers

Headers are metadata.

Format:

```http
Key: Value
```

Think of headers as instructions attached to a package.

---

# Request Headers

Sent by clients.

Examples:

## Authorization

```http
Authorization: Bearer token
```

Used for authentication.

---

## User-Agent

```http
User-Agent: Chrome
```

Identifies client software.

---

## Origin

```http
Origin: https://frontend.com
```

Used for CORS.

---

# General Headers

Work for both requests and responses.

Examples:

```http
Date
Connection
Cache-Control
```

---

# Representation Headers

Describe the body.

## Content-Type

```http
Content-Type: application/json
```

## Content-Length

```http
Content-Length: 2048
```

## Content-Encoding

```http
Content-Encoding: gzip
```

---

# Security Headers

## Strict-Transport-Security

Forces HTTPS.

---

## Content-Security-Policy

Blocks malicious scripts.

---

## Set-Cookie

Creates browser cookies.

Example:

```http
Set-Cookie: session=123
```

# 8. HTTP Methods

Methods describe intent.

---

## GET

Fetch data.

```http
GET /users
```

Should not modify data.

---

## POST

Create data.

```http
POST /users
```

Usually contains a body.

---

## PUT

Replace entire resource.

```http
PUT /users/1
```

---

## PATCH

Update part of resource.

```http
PATCH /users/1
```

---

## DELETE

Remove resource.

```http
DELETE /users/1
```

---

## OPTIONS

Ask server capabilities.

Used heavily in CORS.

---

# 9. Idempotency

Definition:

> Multiple identical requests produce the same final result.

---

## Idempotent Methods

### GET

```http
GET /users/1
```

Repeated calls change nothing.

---

### PUT

Replacing resource repeatedly results in same state.

---

### DELETE

Deleting an already deleted resource leaves state unchanged.

---

## Non-Idempotent Methods

### POST

```http
POST /orders
```

Run twice:

```text
Order #1
Order #2
```

Two resources created.

Not idempotent.

---

# 10. Cross-Origin Resource Sharing (CORS)

Browsers enforce:

```text
Same-Origin Policy
```

Meaning:

```text
frontend.com
```

cannot automatically access:

```text
api.otherdomain.com
```

---

# Simple Request

Browser sends:

```http
Origin: https://frontend.com
```

Server responds:

```http
Access-Control-Allow-Origin: https://frontend.com
```

Browser allows response.

---

# Preflight Request

Triggered when:

- PUT
- DELETE
- PATCH
- Authorization header
- JSON requests

Browser first sends:

```http
OPTIONS /users
```

Server replies:

```http
204 No Content
```

With:

```http
Access-Control-Allow-Origin
Access-Control-Allow-Methods
Access-Control-Allow-Headers
```

If approved:

Actual request is sent.

# 11. HTTP Status Codes

Status codes communicate results.

---

# 1xx Informational

## 100 Continue

Continue upload.

---

# 2xx Success

## 200 OK

Request successful.

## 201 Created

Resource created.

## 204 No Content

Success without body.

---

# 3xx Redirection

## 301 Moved Permanently

Permanent redirect.

---

## 302 Found

Temporary redirect.

---

## 304 Not Modified

Use cached copy.

---

# 4xx Client Errors

## 400 Bad Request

Invalid input.

---

## 401 Unauthorized

Authentication missing.

---

## 403 Forbidden

No permission.

---

## 404 Not Found

Resource doesn't exist.

---

## 405 Method Not Allowed

Wrong HTTP method.

---

## 409 Conflict

Duplicate username.

Duplicate email.

Business rule violation.

---

## 429 Too Many Requests

Rate limit exceeded.

---

# 5xx Server Errors

## 500 Internal Server Error

Unhandled exception.

---

## 501 Not Implemented

Feature not supported.

---

## 502 Bad Gateway

Proxy failure.

---

## 503 Service Unavailable

Maintenance or overload.

---

## 504 Gateway Timeout

Upstream server timed out.

# 12. HTTP Caching

Goal:

Reduce bandwidth.

Improve performance.

---

# First Request

Server sends:

```http
Cache-Control
ETag
Last-Modified
```

Example:

```http
ETag: abc123
```

---

# Second Request

Client sends:

```http
If-None-Match: abc123
```

---

# Resource Unchanged

Server returns:

```http
304 Not Modified
```

No payload transferred.

Browser uses cache.

---

# Resource Changed

Server returns:

```http
200 OK
```

with updated data.

---

# 14. Compression

Compression reduces payload size.

Example:

```text
26 MB JSON
```

Compressed:

```text
3.8 MB gzip
```

Benefits:

- Faster responses
- Lower bandwidth
- Better user experience

Common algorithms:

- gzip
- brotli
- deflate

# 15. Handling Large Data Transfers

# Large Uploads

Images and videos should not be sent as JSON.

Use:

```http
multipart/form-data
```

Example:

```html
<input type="file">
```

Files are separated by boundaries.

---

# Large Downloads

Server streams data gradually.

Headers:

```http
Content-Type: text/event-stream
Connection: keep-alive
```

Benefits:

- Lower memory usage
- No timeouts
- Faster perceived performance

# 16. HTTPS, SSL, and TLS

HTTP is not encrypted.

Anyone intercepting traffic can read it.

---

## SSL

Old security protocol.

Now obsolete.

---

## TLS

Modern replacement.

Provides:

### Encryption

Prevents eavesdropping.

### Integrity

Prevents tampering.

### Authentication

Verifies server identity.

---

## HTTPS

HTTPS is simply:

```text
HTTP + TLS
```

Example:

```text
https://example.com
```

instead of:

```text
http://example.com
```

# 18. Best Practices

### Always Use HTTPS

Never expose sensitive data over HTTP.

---

### Return Correct Status Codes

Use:

```http
201 Created
```

instead of:

```http
200 OK
```

for resource creation.

---

### Compress Responses

Enable:

```text
gzip
```

or

```text
brotli
```

---

### Use Caching

Reduce server load.

---

### Keep APIs Stateless

Never rely on server memory.

---

### Validate Inputs

Never trust client data.

# 19. Common Interview Questions

## Q1

What is HTTP?

**Answer:**
An application-layer protocol used for communication between clients and servers.

---

## Q2

Why is HTTP called stateless?

**Answer:**
Because each request is independent and the server does not remember previous requests.

---

## Q3

Difference between PUT and PATCH?

**Answer:**

PUT replaces the entire resource.

PATCH updates only specific fields.

---

## Q4

What is idempotency?

**Answer:**
Executing the same request multiple times produces the same final server state.

---

## Q5

What is CORS?

**Answer:**
A browser security mechanism that controls cross-origin requests.

---

## Q6

Difference between 401 and 403?

**Answer:**

401 → Not authenticated.

403 → Authenticated but not authorized.

---

## Q7

What is HTTPS?

**Answer:**
HTTP running over TLS encryption.

HTTP is the foundation of backend engineering.

Key concepts every backend engineer must master:

- Stateless communication
- Client-server architecture
- HTTP methods
- Headers
- Status codes
- CORS
- Caching
- Compression
