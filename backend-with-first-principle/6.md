# 1. Introduction to Routing

Routing is one of the most fundamental concepts in backend development.

Whenever a request reaches a server, the server must answer a simple question:

> Which piece of code should handle this request?

The mechanism that determines this is called **Routing**.

Routing maps:

```text
HTTP Method + URL Path
```

to

```text
Specific Backend Logic
```

Example:

```http
GET /users
```

might execute:

```ts
getAllUsers()
```

while:

```http
POST /users
```

might execute:

```ts
createUser()
```

Even though both use the same path:

```text
/users
```

they perform completely different operations because the HTTP methods differ.

---

# 2. Why Routing Exists

Imagine a backend without routing.

Every request arrives at the server.

The server would have no way to know:

- Which resource is requested
- Which function to execute
- What response to return

Routing acts like a traffic controller.

```text
Incoming Request
       |
       V
    Router
       |
       V
Correct Handler
```

Without routing, APIs would be impossible to organize.

---

# 3. How Routing Works

When a request arrives:

```http
GET /users
```

the server performs:

### Step 1

Read HTTP method.

```text
GET
```

### Step 2

Read URL path.

```text
/users
```

### Step 3

Search routing table.

Example:

```text
GET     /users      -> getUsers()
POST    /users      -> createUser()
GET     /books      -> getBooks()
DELETE  /users/:id  -> deleteUser()
```

### Step 4

Execute matching handler.

---

# Route Matching Formula

A route is uniquely identified by:

```text
HTTP Method + URL Path
```

Example:

```http
GET /users
```

and

```http
POST /users
```

are completely different routes.

---

# 4. Route Matching

The router compares incoming requests against registered routes.

Example routes:

```text
GET /users
GET /books
POST /users
```

Incoming request:

```http
GET /books
```

Match found:

```text
GET /books
```

Handler executes.

---

# Routing Flow

```text
Request
   |
   V
Read Method
   |
Read Path
   |
Find Match
   |
Execute Handler
   |
Send Response
```

# 5. Static Routes

Static routes have fixed paths.

They never change.

---

## Example

```http
GET /products
```

Static route:

```text
/products
```

Always identical.

---

## More Examples

```http
GET /users
POST /users
GET /books
GET /products
```

All are static routes.

---

## Characteristics

### Predictable

Always same structure.

### Easy to Match

No variable components.

### Common for Collections

Examples:

```http
GET /users
GET /orders
GET /products
```

Usually return lists.

---

# Example

Request:

```http
GET /books
```

Response:

```json
[
  {
    "id": 1,
    "title": "Clean Code"
  }
]
```

The route path never changes.

---

# 6. Dynamic Routes

Static routes cannot identify individual resources.

Example:

```http
GET /users
```

returns all users.

But what if we need:

```text
User #123
```

Dynamic routes solve this problem.

---

## Example

```http
GET /users/123
```

The value:

```text
123
```

changes dynamically.

---

Dynamic route pattern:

```text
/users/:id
```

Meaning:

```text
Any value after /users/
```

is accepted.

---

# Benefits

Allows:

- User lookup
- Product lookup
- Order lookup
- Resource-specific operations

---

# 7. Path Parameters

Path parameters are variables embedded directly in the URL path.

---

## Example

Route:

```text
/users/:id
```

Request:

```http
GET /users/123
```

Extracted parameter:

```json
{
  "id": "123"
}
```

---

## Multiple Parameters

Route:

```text
/users/:userId/posts/:postId
```

Request:

```http
GET /users/10/posts/50
```

Extracted:

```json
{
  "userId": "10",
  "postId": "50"
}
```

---

# Why Path Parameters Matter

Path parameters identify:

```text
Specific Resource
```

Examples:

```http
/users/1
/orders/55
/products/100
```

They answer:

> Which exact resource do you want?

---

# Path Parameter vs Static Route

Static:

```http
/users
```

Meaning:

```text
All users
```

Dynamic:

```http
/users/1
```

Meaning:

```text
One specific user
```

---

# 8. Query Parameters

Query parameters provide extra information.

Unlike path parameters, they are not part of the resource identity.

---

## Syntax

Start with:

```text
?
```

Example:

```http
/products?page=2
```

---

## Structure

```text
key=value
```

Example:

```http
/search?query=nodejs
```

Key:

```text
query
```

Value:

```text
nodejs
```

---

## Multiple Query Parameters

```http
/products?page=2&sort=price
```

Parsed as:

```json
{
  "page": "2",
  "sort": "price"
}
```

---

# Common Uses

## Pagination

```http
GET /users?page=3
```

---

## Searching

```http
GET /users?name=john
```

---

## Sorting

```http
GET /products?sort=price
```

---

## Filtering

```http
GET /products?category=laptop
```

---

# Path Parameters vs Query Parameters

Path Parameter:

```http
/users/123
```

Meaning:

```text
Which user?
```

---

Query Parameter:

```http
/users?page=2
```

Meaning:

```text
How should users be returned?
```

---

# Rule of Thumb

Path Parameter:

```text
Resource Identity
```

Query Parameter:

```text
Filtering / Metadata
```

# 9. Nested Routes

Nested routes express relationships between resources.

---

## Example

```http
GET /users/123/posts
```

Meaning:

```text
Get posts belonging to user 123
```

---

More specific:

```http
GET /users/123/posts/456
```

Meaning:

```text
Get post 456 owned by user 123
```

---

# Route Breakdown

```text
/users
```

Users collection.

---

```text
123
```

Specific user.

---

```text
posts
```

Posts collection.

---

```text
456
```

Specific post.

---

# Benefits

### Better Organization

Resources grouped logically.

### More Readable

Relationship is obvious.

### REST Friendly

Widely used in APIs.

# 10. Route Versioning

APIs evolve.

Sometimes breaking changes are unavoidable.

Versioning allows multiple API versions to coexist.

---

## Example

Version 1:

```http
/api/v1/products
```

Version 2:

```http
/api/v2/products
```

---

# Why Version APIs?

Suppose response changes.

Version 1:

```json
{
  "name": "Laptop"
}
```

Version 2:

```json
{
  "productName": "Laptop"
}
```

Existing frontend applications would break.

Versioning prevents this.

---

# Common Versioning Styles

## URL Versioning

```http
/api/v1/users
```

Most common.

---

## Header Versioning

```http
API-Version: 2
```

---

## Accept Header Versioning

```http
Accept: application/vnd.api.v2+json
```

Less common.

---

# 11. API Deprecation

Deprecation means:

```text
Old version still works
but will be removed later
```

Example:

```text
v1 -> Deprecated
v2 -> Current
```

Benefits:

- Smooth migration
- No sudden breakage
- Better developer experience

---

# Deprecation Lifecycle

```text
Release v2
     |
Deprecate v1
     |
Notify Clients
     |
Remove v1
```

# 12. Catch-All Routes

A catch-all route handles unmatched requests.

---

## Problem

Request:

```http
GET /random-route
```

No matching route exists.

Without handling:

```text
Confusing error
```

---

## Solution

Catch-all route.

Example:

```text
*
```

or

```text
/*
```

---

# Behavior

```text
Route Match Found?
       |
      No
       |
       V
Catch-All Route
       |
       V
404 Response
```

---

## Example Response

```json
{
  "message": "Route not found"
}
```

Status:

```http
404 Not Found
```

---

# Why Catch-All Routes Matter

Benefits:

- Better UX
- Cleaner API behavior
- Easier debugging

# 14. REST API Routing Conventions

Good:

```http
GET /users
POST /users
GET /users/1
DELETE /users/1
```

Resource-based.

---

Bad:

```http
GET /getUsers
POST /createUser
DELETE /deleteUser
```

Verb-heavy design.

---

Preferred:

```text
Nouns in URLs
Methods define actions
```

# 15. Route Design Best Practices

### Use Nouns

Good:

```http
/users
```

Bad:

```http
/getUsers
```

---

### Keep URLs Predictable

Avoid:

```http
/user-data-list-info
```

Use:

```http
/users
```

---

### Use Query Parameters for Filtering

Good:

```http
/users?page=2
```

---

### Use Path Parameters for Identity

Good:

```http
/users/123
```

---

### Version Public APIs

Example:

```http
/api/v1/users
```

---

### Always Handle Unknown Routes

Return:

```http
404 Not Found
```

# 16. Common Routing Mistakes

## Mistake 1

Using query parameters for resource identity.

Bad:

```http
/users?id=123
```

Better:

```http
/users/123
```

---

## Mistake 2

Ignoring API versioning.

---

## Mistake 3

Creating deeply nested routes.

Bad:

```http
/users/1/orders/2/items/3/reviews/4/comments/5
```

Too complex.

---

## Mistake 4

Using verbs in URLs.

Bad:

```http
/createProduct
```

---

## Mistake 5

No catch-all route.

# 17. Interview Questions

## Q1

What is routing?

**Answer:**

The process of mapping HTTP requests to specific backend handlers.

---

## Q2

Difference between static and dynamic routes?

**Answer:**

Static routes have fixed paths.

Dynamic routes contain variable parameters.

---

## Q3

What are path parameters?

**Answer:**

Variables embedded directly in the URL path used to identify resources.

---

## Q4

What are query parameters used for?

**Answer:**

Filtering, searching, sorting, and pagination.

---

## Q5

Why use API versioning?

**Answer:**

To introduce breaking changes without affecting existing clients.

---

## Q6

What is a catch-all route?

**Answer:**

A fallback route that handles unmatched URLs, usually returning a 404 response.

---

# 18. Summary

Routing is the mechanism that directs incoming HTTP requests to the correct backend logic.

Key concepts:

- Static Routes
- Dynamic Routes
- Path Parameters
- Query Parameters
- Nested Routes
- Versioning
- Deprecation
- Catch-All Routes

Core Routing Formula:

```text
HTTP Method + URL Path
           ↓
      Route Match
           ↓
      Handler Logic
           ↓
        Response
```

Mastering routing is essential because every backend framework—Express.js, NestJS, Spring Boot, Django, FastAPI, Laravel, and ASP.NET—uses routing as the foundation for request handling.
