# 1. Introduction

Every backend application eventually faces two critical questions:

```text
Who are you?
```

and

```text
What are you allowed to do?
```

The first question is solved through:

```text
Authentication
```

The second question is solved through:

```text
Authorization
```

Almost every modern application uses these concepts:

- Banking Apps
- E-Commerce Platforms
- Social Media
- SaaS Products
- Enterprise Software
- Cloud Platforms

Without authentication and authorization, there is no security.

---

# 2. Authentication vs Authorization

Many beginners confuse these concepts.

They solve different problems.

---

# Authentication

Authentication answers:

> Who are you?

The system verifies identity.

Examples:

- Username + Password
- OTP
- Biometrics
- JWT
- Session

---

Example:

```text
User claims:
"I am John"
```

Authentication verifies whether that claim is true.

---

# Authorization

Authorization answers:

> What can you do?

The system determines permissions.

---

Example:

```text
User: John
Role: Admin
```

Permissions:

```text
Read Users
Create Users
Delete Users
```

---

Another user:

```text
Role: Customer
```

Permissions:

```text
Read Products
Place Orders
```

Cannot:

```text
Delete Users
```

---

# Easy Memory Trick

Authentication:

```text
Identity
```

Authorization:

```text
Permission
```

---

# 3. Why Authentication Exists

Imagine an online banking system.

Without authentication:

```http
GET /bank-account
```

Anyone could access anyone's account.

The server needs a reliable mechanism to identify users.

Authentication establishes trust.

---

# 4. Evolution of Authentication

Understanding history explains modern systems.

---

# Era 1: Implicit Trust

Before technology, identity was verified through:

- Reputation
- Community trust
- Face recognition

Example:

```text
Village elder confirms identity.
```

Problem:

```text
Not scalable.
```

---

# Era 2: Physical Authentication

Medieval societies used:

```text
Wax Seals
```

Documents were sealed by trusted authorities.

Authentication depended on:

```text
Something You Have
```

Problem:

```text
Forgery
```

---

# Era 3: Passphrases

Telegraph operators used:

```text
Secret Passphrases
```

Authentication became:

```text
Something You Know
```

This idea survives today as passwords.

---

# Era 4: Computer Passwords

1960s Mainframes introduced:

```text
Username + Password
```

Initially passwords were stored:

```text
Plain Text
```

Very dangerous.

Example:

```text
password123
```

stored exactly as:

```text
password123
```

A database leak exposed everything.

---

# Birth of Hashing

Instead of storing passwords:

```text
password123
```

Store:

```text
5e884898da...
```

A one-way transformation.

---

# Era 5: Multi-Factor Authentication (MFA)

One factor became insufficient.

MFA combines:

---

## Something You Know

```text
Password
```

---

## Something You Have

```text
Phone
OTP
Security Key
```

---

## Something You Are

```text
Fingerprint
Face Scan
Retina Scan
```

---

# Future Trends

- Passwordless Login
- Passkeys
- Post-Quantum Cryptography
- Decentralized Identity
- Behavioral Biometrics

# 5. Passwords and Hashing

Passwords should NEVER be stored directly.

---

# Plain Text Storage

Bad:

```json
{
  "email": "john@gmail.com",
  "password": "secret123"
}
```

Database breach:

```text
All passwords exposed.
```

---

# Hashed Storage

Store:

```json
{
  "passwordHash": "8d969eef6ecad3..."
}
```

instead.

---

# What is Hashing?

Hashing transforms data into a fixed-length value.

Example:

```text
secret123
```

becomes:

```text
8d969eef6ecad3...
```

---

Properties:

### One-Way

Cannot reverse hash.

---

### Deterministic

Same input → Same output.

---

### Fast Verification

Compare hashes.

---

# Password Verification

User enters:

```text
secret123
```

Server:

```text
Hash Input
      ↓
Compare Hashes
      ↓
Match?
```

If yes:

```text
Authenticated
```

---

# Common Algorithms

Modern:

- bcrypt
- Argon2
- scrypt

Avoid:

- MD5
- SHA1

for password storage.

# 6. Modern Authentication Fundamentals

Modern authentication typically uses:

```text
User
  ↓
Login
  ↓
Identity Proof
  ↓
Token or Session
  ↓
Authenticated Requests
```

Three important concepts:

1. Sessions
2. Cookies
3. JWTs

---

# 7. Sessions

HTTP is stateless.

Every request is independent.

Problem:

```text
Server forgets who you are.
```

---

# Session Solution

After login:

```text
User Authenticated
       ↓
Create Session
       ↓
Generate Session ID
```

Example:

```text
session_abc123
```

---

Stored in:

- Memory
- Redis
- Database

---

# Session Storage

Server:

```json
{
  "session_abc123": {
    "userId": 10
  }
}
```

---

Client receives:

```text
session_abc123
```

and sends it back on every request.

---

# Session Flow

```text
Login
   ↓
Create Session
   ↓
Store in Redis
   ↓
Send Session ID
   ↓
Future Requests
   ↓
Lookup Session
```

---

# Advantages

- Easy logout
- Easy revocation
- Centralized control

---

# Disadvantages

- Requires storage
- Harder scaling
- Session synchronization

---

# 8. Cookies

Cookies store small pieces of data in browsers.

---

Server Response:

```http
Set-Cookie: sessionId=abc123
```

Browser stores it.

---

Future requests:

```http
Cookie: sessionId=abc123
```

Automatically attached.

---

# Important Cookie Flags

## HttpOnly

JavaScript cannot read cookie.

Protects against XSS.

---

## Secure

Only sent over HTTPS.

---

## SameSite

Reduces CSRF attacks.

---

# Typical Usage

Store:

```text
Session IDs
```

or

```text
Authentication Tokens
```

inside cookies.

---

# 9. JWT (JSON Web Tokens)

JWT solves scalability problems.

---

# Why JWT Exists

Millions of sessions require storage.

Storage means:

- Memory cost
- Database cost
- Synchronization cost

JWT removes server-side session storage.

---

# JWT Structure

Three parts:

```text
Header.Payload.Signature
```

Example:

```text
xxxxx.yyyyy.zzzzz
```

---

# Header

Contains metadata.

Example:

```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

---

# Payload

Contains claims.

Example:

```json
{
  "sub": 123,
  "role": "admin"
}
```

---

# Signature

Created using server secret.

Purpose:

```text
Prevent Tampering
```

---

# JWT Workflow

Login:

```text
User Authenticated
      ↓
Generate JWT
      ↓
Send JWT
```

---

Future Requests:

```http
Authorization: Bearer JWT
```

Server verifies signature.

No database lookup required.

---

# Advantages

- Stateless
- Scalable
- Fast verification

---

# Disadvantages

- Hard revocation
- Token leakage risk
- Expiration management

---

# 10. Stateful Authentication

Uses:

```text
Sessions + Cookies
```

---

Workflow:

```text
Login
   ↓
Create Session
   ↓
Store in Redis
   ↓
Send Session ID Cookie
   ↓
Lookup Session Every Request
```

---

Characteristics:

### Server Stores State

Yes.

### Easy Logout

Yes.

### Easy Revocation

Yes.

---

# Best For

- Traditional Web Applications
- Internal Dashboards
- Admin Panels

Workflow:

```text
Login
   ↓

   ↓
Send JWT

Future Requests
```

---

Characteristics:

### Server Storage

No.

### Easy Scaling

Yes.

No.

# 12. API Key Authentication

Designed for:

```text
Machine-to-Machine Communication
```

---

Example:

Backend calling AI API.

Request:

```http
Authorization: Bearer sk_xxxxx
```

or

```http

```

---

Common Usage

- Payment Gateways
- AI APIs

- Internal Services

# Advantages

Simple.

---

# Disadvantages

If leaked:

```text

```

until revoked.

# 13. OAuth 2.0

OAuth solves:

```text
Delegated Authorization
```

---

Problem:

Travel app wants Gmail access.

Old method:

```text
Share Gmail Password
```

Dangerous.

---

OAuth Solution

```text
User
   ↓
Google Login
   ↓
Consent Screen
   ↓
Permission Granted
   ↓
Access Token Issued
```

---

App never sees password.

---

# OAuth Roles

### Resource Owner

User

---

### Client

Application

---

### Authorization Server

Google

---

### Resource Server

Google APIs

---

# OAuth Purpose

Authorization.

Not identity verification.

OAuth alone doesn't verify identity.

OIDC adds:

```text
ID Token
```

Usually a JWT.

---

Contains:

```json
{
  "email": "john@gmail.com",
  "name": "John"
}
```

---

Used by:

```text
Sign In With Google
Sign In With Microsoft
Sign In With GitHub
```

---

# Easy Memory Trick

OAuth:

```text
Permissions
```

OIDC:

```text
Identity
```

# 15. Role-Based Access Control (RBAC)

Authentication identifies users.

Authorization controls actions.

---

# Example Roles

## User

Can:

```text
Read Products
Place Orders
```

Cannot:

```text
Delete Products
```

---

## Admin

Can:

```text
Read
Write
Delete
Manage Users
```

---

# RBAC Structure

```text
User
  ↓
Role
  ↓
Permissions
```

---

Example:

```json
{
  "role": "admin"
}
```

---

# Authorization Check

```text
Request
   ↓
Authenticated?
   ↓
Role?
   ↓
Permission?
   ↓
Allow / Deny
```

---

Unauthorized request:

```http
403 Forbidden
```

# 17. Security Best Practices

---

# Use HTTPS

Never transmit credentials via HTTP.

---

# Hash Passwords

Use:

- bcrypt
- Argon2

Never plain text.

---

# Enable MFA

Adds another security layer.

---

# Use Short JWT Lifetimes

Reduces exposure.

---

# Store Secrets Securely

Never hardcode:

```text
JWT_SECRET
```

inside source code.

---

# Rotate Credentials

Regularly replace keys.

---

# 18. Common Attacks

## Brute Force

Trying many passwords.

Solution:

```text
Rate Limiting
MFA
```

---

## Credential Stuffing

Using leaked passwords.

Solution:

```text
MFA
```

---

## Session Hijacking

Stealing session cookies.

Solution:

```text
HTTPS
HttpOnly
Secure Cookies
```

---

## JWT Theft

Stealing access token.

Solution:

```text
Short Expiration
HTTPS
```

---

## Timing Attacks

Attackers measure response times.

Bad:

```text
User Not Found
```

returns instantly.

Wrong password takes longer.

---

Solution:

Use constant-time comparisons and consistent response delays.

# 20. Interview Questions

## Q1

Difference between authentication and authorization?

**Answer:**

Authentication verifies identity.

Authorization determines permissions.

---

## Q2

Why are passwords hashed?

**Answer:**

To prevent exposing actual passwords if a database is compromised.

---

## Q3

Difference between sessions and JWT?

**Answer:**

Sessions store state on the server.

JWT stores state inside the token.

---

## Q4

What problem does OAuth solve?

**Answer:**

Delegated authorization without sharing passwords.

---

## Q5

What does OIDC add to OAuth?

**Answer:**

Identity verification through ID Tokens.

---

## Q6

What status code is returned when authorization fails?

**Answer:**

```http
403 Forbidden
```

---

## Q7

What status code is commonly returned when authentication fails?

**Answer:**

```http
401 Unauthorized
```

# 21. Summary

Authentication and authorization are the backbone of backend security.

Core Concepts:

```text
Authentication
      ↓
Who Are You?
```

```text
Authorization
      ↓
What Can You Do?
```

Modern Authentication Tools:

- Sessions
- Cookies
- JWTs
- API Keys
- OAuth 2.0
- OpenID Connect

Authorization Models:

- RBAC
- Permission Systems

Golden Security Rule:

```text
Never trust incoming requests.
Always verify identity.
Always verify permissions.
```

Backend Security Flow:

```text
Request
   ↓
Authentication
   ↓
Authorization
   ↓
Business Logic
   ↓
Response
```
